# 生产部署（Production）

> 最后更新：2026-09-26
> 本文讲生产环境的部署形态、安全、可观测与升级。镜像与 Compose 细节见[容器部署](docker.md)。

## 1. 部署形态选择

- **单容器（推荐）**：一个进程、一个端口同时提供 API 与页面，最贴近"零运维"的定位。见[容器部署](docker.md)。
- **编排平台（K8s 等）**：本服务**只认环境变量**，直接用平台的 env / Secret 注入即可，无需挂配置文件。
- **前后端分开部署**：前端产物烧入 API 的绝对地址（`VITE_API_BASE_URL`），仅在确有必要时使用。

## 2. 必配环境变量

| 变量 | 生产建议 |
|------|----------|
| `DATABASE_URL` | **必填**，缺失即启动失败。 |
| `SECURITY_KEY` | **生产强烈建议显式设置**（64 位 hex，`openssl rand -hex 32`）。详见下文"安全实践"。 |
| `PORT` | 按需；默认 23352。 |
| `SENTRY_DSN` | 需要错误上报时设置（后端项目）。 |
| `CORS_ALLOWED_ORIGINS` | 同源部署**无需设置**；仅前后端分离部署时按需填白名单。 |
| `STATIC_DIR` | 单镜像内由镜像预设为 `/app/web`；留空则退化为纯 API。 |
| `VITE_SENTRY_DSN` | 前端 Sentry，**构建期内联**。 |
| `VITE_API_BASE_URL` | 仅前后端分开部署时设置，**构建期内联**。 |

优先级（低 → 高）：内置默认值 < `.env` < 真实系统环境变量；**空字符串一律等同"未设置"**。完整字典见[配置与参数](../user-guide/configuration.md)。

## 3. 安全实践

- **`SECURITY_KEY`**：数据源密码用 AES-256-GCM 加密存储，密钥来自 `SECURITY_KEY`。留空时系统首次启动会**随机生成并持久化到数据库**（`bi_setting` 表），此后复用同一把。
  - ⚠️ **已有加密数据不可换 key**：换了 key 就再也解不开存量密码。若显式配置，务必保证多个副本 / 多次重启用的是同一把，且与库内已加密数据对应的 key 一致。
- **数据源密码**：API 响应中**永不回显**（`password` 字段 `json:"-"`），仅落库前加密。
- **分享密码**：以哈希（bcrypt）存储，对外只暴露"是否有密码"（`has_password`）。
- **CORS**：默认放开所有来源（平台 API 无登录态，CORS 不构成安全边界）；将来引入认证或需要限定域名时，用 `CORS_ALLOWED_ORIGINS` 收紧。
- **`VITE_*` 是构建期内联，绝不能放密钥**。

## 4. 可观测与健康检查

- **`GET /health`**：只证明**进程活着**，它**不探库**，不代表 `DATABASE_URL` 可连。要确认连通性，请打真实业务接口（如 `GET /api/datasets`），其错误串会直接印出连接目标。
- **Sentry**：前后端是两个**独立项目**（`SENTRY_DSN` 与 `VITE_SENTRY_DSN`），可分别接入。
- 镜像自带 `/health` 的 HEALTHCHECK。

## 5. 缓存与静态托管

- `assets/` 下带内容哈希的产物走 `immutable` 长缓存，其余路径 `no-cache`。
- 静态目录读不到 `index.html` 会**启动即失败**（fail-fast，避免跑起来后整站 404）。
- 路径分流：`/api`、`/mcp`、`/health` 及其子路径走后端，未匹配返回 JSON 404（不会回落成 HTML）；其余路径查静态目录、未命中回落 `index.html`。

## 6. 数据与迁移

- 数据库 schema 由 **goose 版本化迁移**管理（迁移文件通过 `embed.FS` 内嵌进二进制），**随服务启动自动应用**，无需手工导 schema。
- 业务表采用**软删除**（打 `deleted_at`，绝不物理删），级联在同一事务内显式完成；查询记录表 (`bi_query`) 永不物理删。

## 7. 升级与回滚

- **迁移前先备份**：迁移随启动自动应用，升级前先对 `DATABASE_URL` 指向的库做一次备份。
- **镜像用不可变 tag**：用版本号或提交 sha 打 tag，避免 `latest` 无法区分版本、难以回滚。
- **回滚注意 `SECURITY_KEY`**：回滚到旧版本时，`SECURITY_KEY` 必须与库里已加密数据对应的 key 保持一致（留空时 key 落在数据库里，容器重建会自动复用；显式配置时须保持同一把）。
- **升级到列 ID 契约（`fieldId`）需先跑一次性迁移**：图表/仪表盘的列引用从「列名」改为「列的稳定 id」，存量配置必须先执行 `./server -migrate-column-ids`（dry-run 扫描）确认无误后再带 `-apply` 跑一遍写库，**然后**才放量新版本。顺序颠倒时新进程读旧引用会静默丢弃过滤条件（返回放大后的错数而非报错）。
