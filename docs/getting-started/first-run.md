# 第一次启动（First Run）

> 最后更新：2026-10-31
> 面向刚把 Data Insights 跑起来的人：首启向导、管理员建立与恢复、加同事，以及几个常见疑问的口径。
> 部署方式本身见[快速开始](quick-start.md)；环境变量字典见[配置项字典](../user-guide/configuration.md)。

## 1. 首启向导：建管理员

首次启动时库里还没有管理员，平台会引导你用以下**两条路径之一**建立（都是幂等的：只要库里已存在有效管理员，就不再动作）：

### 路径一：一次性 bootstrap token（默认，推荐交互式部署）

1. 启动后看部署日志，会有一行 `BOOTSTRAP TOKEN: <令牌>`（**明文只打印这一次**，库里只存 sha256，30 分钟有效）：

   ```bash
   docker logs data-insights | grep BOOTSTRAP
   ```

2. 打开 `http://<主机>:23352`，在引导页用该 token 注册第一个管理员账号。
3. token 过期或没来得及用：重启一次容器会重新生成一个（旧的作废）。

### 路径二：环境变量无头建号（自动化 / 无法看日志的部署）

同时设置 `ADMIN_USERNAME` + `ADMIN_PASSWORD`（**必须成对**，只设一个会被忽略并告警）后启动，平台直接创建该管理员并跳过 token 打印。注意 `ADMIN_PASSWORD` 写进 env 会出现在 `docker inspect` / `compose config` 里，生产建议用 Secret 注入，建号后从 env 中移除。

> 并发抢注（多副本同时首启）由数据库 advisory lock 串行化，只会建成一个管理员。

## 2. 加同事

管理员登录后，在「账号」页为同事建号（`POST /api/users`，仅管理员可用）：建号 / 改资料 / 禁用 / 重置口令都在这一处。普通用户自己不开放注册——注册端点仅在首管 bootstrap 阶段可用。

## 3. 忘记口令（已知边界）

管理员口令**没有自助找回**，恢复走显式开启的恢复通道：

1. 平时 `ADMIN_RESET_TOKEN` **留空 = 恢复通道关闭**（推荐默认关闭）。
2. 忘记口令时：给部署环境补设 `ADMIN_RESET_TOKEN=<任意强随机值>` 并重启容器，恢复通道即开启；然后调用（或在恢复页提交）`POST /api/auth/recover-admin`，body 为 `{reset_token, new_password}`。
3. 令牌**单次有效**：成功重置后同一令牌再提交会被拒绝（错误码 20200），且该管理员的全部现存会话被撤销；**成功后请更换或清空该环境变量**。
4. 若你有第二个管理员，也可由它直接为同事重置口令（见上节），无需恢复通道。

**单人部署且从未开启恢复通道**：同样按上面第 2 步补设 `ADMIN_RESET_TOKEN` 并重启即可——通道是否开启是运行时条件，事后补开不需要访问数据库。若连部署环境（env / 容器）都失控了，只能由持有数据库的人在用户表上处理，这是已知的最后手段。

## 4. 常见疑问口径

- **刷新页面会掉登录吗？** 当前会话令牌**只存内存**（出于安全不做 localStorage 长期明文驻留），所以刷新页面后需要重新登录；「刷新不掉登录」由前端身份壳（issue #218，R-93）跟进解决。PAT（机器 token）不受影响——它由调用方自行保存。
- **登录了就等于数据受保护了吗？** 不等于。默认 `AUTH_ENFORCE=off` 时资源端点仍对匿名开放，登录只是获得身份；**对外暴露务必设 `AUTH_ENFORCE=on`**。逐项「哪些端点强制 Bearer、哪些仍匿名」的清单见[配置字典](../user-guide/configuration.md)。
- **内置示例数据集**：首启后可一键加载示例订单数据直达首图，可忽略 / 移除，不影响真实数据。
