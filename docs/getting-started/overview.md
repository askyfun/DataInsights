# 概览（Overview）

> 最后更新：2026-10-17
> 一句话：Data Insights 是什么、给谁用、要去哪儿。

## 1. Data Insights 是什么

Data Insights 是一个**拖拽式 BI 可视化分析平台**（MVP），面向**单团队内网自助分析**：不用搭数据建模平台、不用手写 SQL —— 连上数据源、建好数据集，把字段拖进槽位就能即时出图，并能把结果一键分享。

主流程：

```
数据源  →  数据集  →  拖拽配图（即时预览）  →  保存 / 复制地址栏  →  仪表盘
```

- 后端是 Go 单二进制，直连四种数据库方言（PostgreSQL / MySQL / ClickHouse / StarRocks）；前端是 React 19 + TypeScript + ECharts。
- 部署形态是**单镜像单进程**：一个容器、一个端口（23352）同时提供 API 与页面。

## 2. 核心概念

- **数据源**：一个可连的数据库连接（四种方言之一），支持连接测试与表 / 列 / 数据浏览。
- **数据集**：在数据源之上定义"用哪张表或哪段自定义 SQL"，并给每一列定义类型与角色（维度 / 指标）。列拥有**稳定 id**，图表配置引用的是该 id 而不是列名。
- **物理表 vs 自定义 SQL**：数据集的两种模式 —— 直接选表称**「物理表」**，写一段 SQL 称**「自定义 SQL」**。这两个术语固定，别混用。
- **图表**：由「图型 + 维度组 + 指标组 + 过滤 / 排序」构成；配置持久化为带 `version` 的**图表配置文档**（历史结构在加载时自动迁移）。
- **槽位（slot）**：拖拽落点。不同图型有不同的维度 / 指标槽位，把字段拖入槽位即改变查询。
- **分享**：查询记录的短码直链（`?q=<短码>`）——「地址栏即分享」，打开即还原当时的配置（不可变快照）。
  早期的口令分享（密码 + 过期）已下线（issue #112），不再有分享清单 / 吊销入口。
- **抽取数据集**：把本地 `.csv` / `.xlsx`（单文件 ≤50MB）灌入指定的抽取存储数据源并自动生成数据集；
  抽取存储支持 starrocks / mysql / postgresql（`EXTRACT_DATASOURCE_ID`）。
- **预警**：对指标设阈值规则，后台按间隔评估、落触发记录，可选 SMTP 邮件通知（未配置 SMTP 时只落记录）。
- **账号**：登录 / 24 小时会话、管理员建号 / 重置口令 / 禁用、以及机器用的 PAT（个人访问令牌）。
  开放注册在首个管理员建立后关闭。当前为**渐进启用**：只有账号、令牌与用户管理端点要求 Bearer，既有资源端点仍匿名。
- **查询记录**：每次成功查询落库（内容 hash 去重）并生成短码直链（`?q=<短码>`），"地址栏即分享"；它是**不可变快照**。
- **仪表盘**：12 列栅格上的多图视图，含图表块、文本块与**盘级筛选器**；**一个盘可含多个页面**（底部标签条切换，每页独立布局），打开时只取当前页的块。
- **表面系统**：前端统一的页面骨架 / 色彩 / 字体 / 组件样式规范（详见开发者指南的 design-system）。

术语沿用既有口径（「表面系统」「契约事实源」「盘级筛选器」「槽位」「叙述层」），全仓一致。

## 3. 应用场景

| 典型问题 | Data Insights 怎么解 |
|---|---|
| 想统计一下，却要等数据团队排期建模 | 直接连上业务库，选表或写一段 SQL 建数据集，当场拖图 |
| 换个图型或字段就要重新跑一遍，反复等待 | 拖字段、换图型、改筛选**任一改动即时出图**，拖拽与结果之间没有"Run"割裂 |
| 结果想发群里，但不想让链接内容随数据变化 | 查询记录落库为**不可变快照**，复制地址栏的 `?q=` 短码直链即分享 |
| "这张图当时是什么数"说不清 | 查询记录落库为**不可变快照**，短码直链随时还原 |
| 团队用了多种数据库，工具得跟着换 | 一套界面直连 PG / MySQL / ClickHouse / StarRocks |
| 单张图不够，想要一个视图 | 仪表盘 v1：12 列栅格 + 盘级筛选器，多块联动取数 |

## 4. 对外 Roadmap

> 以下是**产品级方向**，不是排期承诺；越靠后的阶段越依赖尚未触发的条件。

### 现在有什么（已交付）

- 4 方言数据源直连（PostgreSQL / MySQL / ClickHouse / StarRocks），含连接测试、表 / 列元数据与数据预览。
- 数据集（物理表 / 自定义 SQL；列定义含稳定 id、角色、类型）。
- **13 种图型**的拖拽式构建：表格、透视表、KPI 卡、柱状图、折线图、面积图、组合图（双轴）、饼图、漏斗图、雷达图、散点图、直方图、箱线图。图表侧含数据标注、参考线、Top N「其他」合并、同环比、指标占比，以及撤销 / 重做、自动查询、会话内查询历史。
- **表格增强二期**：条件格式、单元格合并、行列转置、迷你图列（另有合计行、序号列、冻结维度列等第一批能力）。
- **本地上传**：`.csv` / `.xlsx`（单文件 ≤50MB）灌入抽取存储并自动生成数据集（需配置 `EXTRACT_DATASOURCE_ID`；存储方言支持 starrocks / mysql / postgresql）。
- **内置示例数据集**：首次启动一键加载示例订单数据并直达首图（可忽略 / 移除），开箱体验零配置。
- 查询记录（内容 hash 去重 + 短码直链，快照语义）。
- 仪表盘 v1（12 列栅格 + 图表块 / 文本块 / 盘级筛选器，一次请求多块联动取数），并已具备**多页面**、**查询容器**、**图表联动**与**归档文件夹树**。
- **指标阈值预警**：规则 CRUD + 后台评估 worker + 触发记录 + 可选 SMTP 邮件通知。
- **账号体系 v1**：登录 / 会话（24h）+ PAT 管理 + **最小用户管理**（管理员建号 / 角色切换 / 禁用 / 重置口令；禁用即刻吊销会话与 PAT）；渐进启用——资源端点仍匿名，登录不等于全站已受保护。
- 前端工程侧：路由级代码分割、根级 ErrorBoundary、`prefers-reduced-motion` 适配、大数据渲染优化（抽稀 / 大图模式）。

### 近期 · 收口（Phase A）

把**已建成但尚未完全接通**的能力接上、把安全门禁补齐、把不可逆的元数据欠账还掉：

- ✅ 分享收口：口令分享已下线（issue #112），查询记录的短码寻址与「复制地址栏」可用，不再有分享清单 / 吊销入口。
- 查询门禁：✅ 查询期表达式白名单校验（#170）；**只读账号**仍属部署侧约束，未在产品内强制。
- ✅ 元数据欠账：`bi_datasource` / `bi_dataset` / `bi_chart` 已补齐 `owner_id` 归属列（#171）。
- 图型轨收尾：✅ 数据标签（#153）与参考线（#116）；**图例与坐标轴配置**仍待补。

### 中期 · 可信消费（Phase B）

从"能画一张图"到"能交付一个多图视图，且口径不打架"：

- ✅ 看板容器（查询容器）、**盘级全局筛选**、跨图联动已交付；下钻仍待补。
- **最小语义层**（字段 / 指标定义 + 查询 dry-plan 校验）—— 它是后续 AI 能力的强制前置。

### 探索方向（Phase C · 组织化）

**仅在**出现账号体系、网络越出内网、接入跨团队 / 外部用户等条件时才会启动：

- ✅ 账号体系 v1（登录 / 会话 / PAT / 管理员建号与禁用）已落地，但当前是**渐进启用**：资源端点仍匿名；RBAC 与资源级权限仍未开始。
- RBAC、**行级安全（RLS）**、多租户，以及历史查询的可见性收回与审计仍待做；启动后需要把资源端点逐个纳入 Bearer 门禁。

### 探索方向（Phase D · 智能与分发）

- **AI 出图**：限定为"已有画布内的自然语言**局部改写**"（换维度 / 换图型 / 加筛选 / 改排序，失败可撤销），而不是"一句话生成整套看板"。
- MCP server 接入、嵌入式分析。
- ⚠️ 以上均为**探索方向**，不给排期；AI 能力排在语义层之后。

### 非目标（Non-goals）

- **不引入后台定时任务 / 调度订阅**：不做报表订阅、ETL 调度或通用任务编排。
  唯一例外是**指标阈值预警的进程内评估 worker**（issue #155）：只评估预警规则，
  边界与常驻成本见[架构文档的 D12](../developer-guide/architecture.md)（裁定记录 #206）。
  后续再出现后台调度需求，仍按「先推翻红线并单独立项」处理。
