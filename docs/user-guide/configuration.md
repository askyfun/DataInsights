# 配置与参数（Configuration）

> 最后更新：2026-10-17
> 本文是环境变量与配置优先级的**参数字典**。完整本地环境搭建见[本地开发环境](../developer-guide/dev-setup.md)。

## 1. 配置的唯一来源

**项目只认环境变量，不提供任何配置文件**（没有 `config.toml` / `config.yaml`）。这条是刻意的：容器化部署下，每个要用户填的值都必须能从外部注入（`docker run -e` / `--env-file` / compose `environment` / K8s env），再挂一份文件只会制造"改了没生效"的歧义。

优先级（低 → 高）：

```
内置默认值  <  仓库根 .env 文件  <  真实系统环境变量
```

- 变量名**不加前缀**：后端进程是唯一读者；而 `DATABASE_URL` / `PORT` 是 12-factor 标准名，云平台（Heroku / Railway / Render / Fly）自动注入的正是裸名。
- **空字符串一律等同"未设置"**，所以 `.env` 里留空占位不会打掉内置默认值。
- **唯一例外**：前端变量必须带 `VITE_` 前缀（Vite 的硬性要求，不是风格选择）。

## 2. 起步：复制模板

```bash
cp .env.example .env    # 然后按需修改
```

`.env` 放在**仓库根**且**不入库**，前后端共用这一份（文件保持 `KEY=value` 裸格式：不加引号、不写 `export`，这样才能被 `docker run --env-file` 直接使用）。

## 3. 变量表

| 变量 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `DATABASE_URL` | **是** | — | PostgreSQL 连接串。缺失时启动 fail-fast 并打印变量名，不会退化成驱动层看不懂的连接失败。 |
| `PORT` | 否 | `23352` | HTTP 监听端口。监听地址固定 `0.0.0.0`，**不提供**覆盖。 |
| `SECURITY_KEY` | 否 | 首启随机生成 | 数据源密码 AES-256-GCM 的加密密钥（64 位 hex）。**留空 = 系统首次启动随机生成（32 字节）并持久化到数据库**，重启 / 容器重建复用同一把，保证已加密密码始终可解；显式配置时环境变量优先。**生产强烈建议显式设置**。 |
| `SENTRY_DSN` | 否 | 空 | 后端 Sentry DSN，留空 = 关闭上报。 |
| `CORS_ALLOWED_ORIGINS` | 否 | 空 | 逗号分隔白名单；**留空 = 放开所有来源**（平台 API 无登录态，CORS 不构成安全边界）。填非空白名单则只回显名单内来源，供将来引入认证后收紧。 |
| `STATIC_DIR` | 否 | 空 | 前端构建产物目录。设置后本进程一并托管页面（未命中回落 `index.html`）；**留空 = 只提供 API**（本地开发默认形态，页面走 Vite dev server）。目录配错即启动失败。 |
| `EXTRACT_DATASOURCE_ID` | 否 | 自举 | 本地文件上传（CSV/XLSX）的落库位置。**留空即可用**——平台会自动复用 `DATABASE_URL` 指向的应用自身 PostgreSQL 作为上传存储（见下方「上传存储怎么定的」）。填一个数据源 id 则改用它作为存储。无论哪种，该数据源都不再是普通数据源：列表隐藏、不能被常规数据集引用；上传表以 `di_extract_<datasetId>` 命名。 |
| `ALERT_EVAL_INTERVAL` | 否 | `300` | 指标预警评估的轮询间隔（秒）。非法值（非整数 / 小于 1）**不 fail-fast**：回退 300 并打 warning。评估器是进程内常驻 goroutine，随主进程退出。 |
| `SMTP_HOST` | 否 | 空 | 预警邮件 SMTP 主机。**留空 = 未配置通知**：评估照常运行、触发记录照常落库，`notify_error` 标注未配置。 |
| `SMTP_PORT` | 否 | `587` | SMTP 提交端口。连接后**若服务器声明 STARTTLS 就升级**，声明 AUTH 才做 PlainAuth；本期不做 465 隐式 TLS（直连 TLS）。 |
| `SMTP_USERNAME` | 否 | 空 | SMTP 认证用户名（服务器声明 AUTH 时使用 PlainAuth）。 |
| `SMTP_PASSWORD` | 否 | 空 | SMTP 认证密码。 |
| `SMTP_FROM` | 否 | 空 | 发件人地址。配了 `SMTP_HOST` 但此项或收件人为空时，通知失败并在 `notify_error` 留档（不会静默）。 |
| `ALERT_NOTIFY_EMAIL` | 否 | 空 | 预警邮件收件人，逗号分隔多个。与 `SMTP_FROM` 同时非空才会真正发送。 |
| `VITE_API_BASE_URL` | 否 | 空 | 前端 API 基础地址。未配置时：生产构建自动同源、开发回退 `http://<当前访问主机名>:23352`。**仅前后端分开部署时**才需配成非空绝对地址。 |
| `VITE_SENTRY_DSN` | 否 | 空 | 前端 Sentry DSN。留空 = 完全跳过 `Sentry.init`，不打点也不上报。 |

> 前端 API 基础地址的**唯一来源**是代码里的 `resolveApiBaseURL`（前端 `lib/api/client.ts`），`VITE_API_BASE_URL` 只是它读取的环境变量。

## 4. 本地文件上传（CSV / XLSX）

拖一个 Excel/CSV 进来就能建数据集，**默认什么都不用配**。

### 4.1 上传存储怎么定的

| `EXTRACT_DATASOURCE_ID` | 行为 |
|------------------------|------|
| 留空（默认） | 复用 `DATABASE_URL` 指向的**应用自身 PostgreSQL**。首次启动时平台自动落一条内部数据源行（名字形如 `data-insights internal storage (upload files)`，在数据源列表里被隐藏），并把它的 id 记进 `bi_setting` 供后续启动复用。 |
| 填某个数据源 id | 用它作为存储。适合希望上传数据与平台元数据**分库存放**的部署。 |

几个要点：

- **不要删那条内部存储数据源。** 它被每个上传数据集通过 `datasource_id` 引用着；删掉之后平台会在下次启动时重建一条，但**旧的上传数据集仍指向旧的 id**，表现为图表能打开、数据为空。需要彻底清理时请连同对应的数据集一起删。
- **换 `SECURITY_KEY` 不用管它。** 数据源口令是加密存储的，换 key 后旧密文解不开——这对**你自己建的数据源**需要手动重填一次口令（既有行为）。而这条内部存储的口令是从 `DATABASE_URL` 推导的，平台会在每次启动时自动对齐，**换 key 后上传功能不受影响**，启动日志会记一行 `Re-wrote the upload storage password`。
- **显式配置优先于自举。** 一旦设了 `EXTRACT_DATASOURCE_ID`，平台不会再自举、也不会覆盖你的选择。
- **自举失败不阻塞启动。** 若应用数据库不可达，平台只把上传入口置灰并记录日志，平台其余功能（已有数据源、仪表盘、分享）照常可用。
- 无论哪种，存储数据源都**从列表隐藏**，且**不能被普通数据集引用**——它是基础设施，不是用户连接。

### 4.2 支持的存储方言

上传存储必须支持这三种之一（由数据源的「类型」决定）：**`postgresql` / `mysql` / `starrocks`**。

> 不需要 StarRocks。用默认的应用自身 PostgreSQL 就够了；只有明确要把上传数据放进已有 MySQL / StarRocks 时才需要填 `EXTRACT_DATASOURCE_ID`。

### 4.3 上限

| 项 | 上限 | 超限表现 |
|----|------|----------|
| 单个文件体积 | **50 MB** | 提示「文件超过 50MB 上限」 |
| 单个文件行数 | **1,000,000 行**（不含表头） | 提示行数上限，并建议先拆分或筛选 |
| 单个文件列数 | **1,000 列** | 提示列数上限，并建议先精简列 |

行数上限与体积上限是两件事：50MB 的窄表可以是上百万行，而摄入时间随行数线性增长——它决定的是你首次上传要等多久。

### 4.4 列类型推断口径

推断只认同形态，**不做「尽力解析」**：某一列只要出现一个与其余值不同形态的脏值，整列退回字符串。

| 会被判为数值 | 会退回字符串 |
|--------------|--------------|
| `1234`、`-5`、`1.5`、`1e5`、`007` | `1,234`（千分位）、`50%`、`$1.50`、`10kg`、`N/A`、`(100)`（会计负数） |

前导零（`007` → 7）与科学计数法（`1e5`）被识别为数值是**有意为之**：它们是合法数值文本，替你「猜」反而会让用户困惑。后者是显式声明「这一列有脏数据」，用户看得见；猜错的数字则看得不见。上传后可在复核弹窗里手动改列类型。

## 5. 前后端共用一份 `.env`

- 后端读**裸名**变量（如 `DATABASE_URL`），前端只消费 `VITE_` 前缀；Vite 通过配置把 `.env` 目录指向仓库根，因此两者共读同一份文件。
- `docker run --env-file .env ...` 可直接使用；编排平台则用各自的 env 注入方式。

## 6. 注意事项

- ⚠️ **`VITE_*` 是「构建期内联」**：值在 `vite build` 时被写进 JS 产物，改完必须重新 build 才生效；也正因如此**绝不可**在里面放密钥。
- ⚠️ `.dockerignore` **必须排除 `.env`**，否则 Vite 会把 `VITE_*` 内联进浏览器包。
- compose 读根 `.env` **只用于变量插值**（`docker-compose.allinone.yml` 里的 `${...}`），本身**不挂 `env_file`**：进容器的只有 `environment:` 里逐个 `${...}` 引用的那几项，其余变量不影响容器。所以**别把无关工具的变量混进这个文件**。
- 静态托管下 `/api`、`/mcp`、`/health` 及其子路径走后端（匹配不到即 JSON 404，**不会回落成 HTML**），其余路径查 `STATIC_DIR` 里的文件、未命中回落 `index.html` 交给前端路由。带内容哈希的 `assets/` 产物走 `immutable` 长缓存，其余 `no-cache`。

## 7. 认证现状：哪些端点强制 Bearer

当前是**渐进式强制认证**（Phase C 之前的状态），登录页出现不等于全站受保护。以下口径与 `backend/cmd/routes.go` 的路由注册逐一对应：

| 范围 | 端点 | 凭据要求 |
|------|------|----------|
| 公开 | `POST /api/auth/register`、`POST /api/auth/login` | 无 |
| **仍匿名** | `/api/datasources*`、`/api/datasets*`、`/api/charts*`、`/api/queries*`、`/api/dashboards*`、`/api/dashboard-folders*`、`/api/alerts*`、`/api/sample-dataset*`、`/health` | 无 |
| 人类或机器 | `GET /api/auth/me`、`DELETE /api/auth/logout` | Bearer（会话或 PAT） |
| 仅人类会话 | `/api/tokens*` | Bearer，且**拒绝 PAT** |
| 仅人类会话 + 管理员 | `/api/users*` | Bearer + 拒绝 PAT + 角色为 `admin` |

要点：

- **资源端点仍匿名可读写**。若把平台暴露到公网，请自行在网络层限制访问，不要仅依赖登录入口；「已登录 = 数据受保护」在当前版本不成立。
- `POST /api/auth/register` 只在**没有任何存活账号**时可用，用于创建首个管理员；之后注册关闭，新增账号只能由管理员在「用户管理」页创建（`POST /api/users`）。
- 禁用账号会立即吊销该用户全部未撤销 token（会话与 PAT），下一跳即失效；最后一个启用中的管理员不可降级、不可禁用。
- 所有 Bearer 校验都是**每次请求实时查库**（不签名、不缓存），撤销与禁用没有生效窗口。
