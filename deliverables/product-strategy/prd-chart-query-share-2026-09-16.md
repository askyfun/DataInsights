## 📌 TL;DR（执行摘要）

- **机制**：每次查询**自动落库**为一条查询记录并生成 **queryId**，地址栏替换为 `?q=<uuid>` → **复制地址栏即分享**；查询都在库里，**历史查询天然可查**，条件完整保存。
- **抄火山 DataWind 的**：id 寻址 · 地址栏即分享入口 · 查询可回溯 · 草稿态（保存后才入文件夹）。**不抄的**：8 位自增数字 id（可枚举 + 无鉴权 = 全库查询历史任人遍历）→ 换**不可猜 UUID**；"每次查询无限落库、不去重" → 降级为 **hash 去重 upsert**；**不引入后台定时清理**（全仓无 redis/asynq/cron 基建）。
- **生命周期的两条硬决策**：**① 查询记录永不物理删除**（`expires_at` 单字段判定软过期：过期后隐于默认视图，但**直链仍可打开、条件 100% 完整还原**）；**② "删除"这个动作从产品里整体消失**（改为「从我视图中移除」，浏览器本地隐藏）。
- **"不真删"已扩展到全部实体**（产品负责人终局裁决）：`bi_datasource` / `bi_dataset` / `bi_dataset_lineage` / `bi_chart` / `bi_share` 五张表全部改为 `deleted_at` 软删除 + 显式级联，**数据库的 `ON DELETE CASCADE` 不再触发**。
- **可见性**：历史查询列表**默认全员共享**——产品负责人已明确接受由此带来的 PII 暴露风险；旧版"仅本人可见 / 需显式发布"的缓解措施**整体废弃**，改为**元数据化列表 + 敏感键脱敏 + L0 使用约定**。
- **代价与风险**：可见性在无账号体系下只能缓解、不能根治（`bi_query.owner_id` 恒 NULL、不参与过滤）；落库改为**前端同步 POST**（见 §5.6），崩溃丢记录的窗口已消除，残留边界是"落库失败静默 + 需重新查询自愈"。
- **规模**：当期逐项加总 **97–148 人日**；**分享闭环（最短见价值路径）17–28 人日**。

## 3. 用户研究洞察（瑞思）

**「复制地址栏」用户真正在意的三件事**（按权重）：**零决策仪式**（不用"点分享→命名→设密码→回传链接"）· **零等待**（结果已在屏幕上）· **可直接贴进 IM**。

### 3.1 四个反噬点与其演变

| # | 反噬点 | v1（URL 携带状态） | 定稿（queryId 落库） |
|---|--------|-------------------|---------------------|
| 1 | 链接过长被 IM 截断 | ★★★ 会投诉 | ✅ **消失**（链接只带一个 id） |
| 2 | 地址栏是"查询"不是"图"，口径变则同链不同数 | 存在 | ⚠️ **更强**——存条件不存结果，链接"永久却内容漂移" |
| 3 | 生命周期 vs 用户以为永久 | 存在 | ⚠️ **换形态**——表现为打开旧链失效（Grafana snapshot 同样有 1h/1d/never 档） |
| 4 | 条件进浏览器历史/IM/代理日志 | 存在 | ⚠️ **转移未消失**——地址栏变干净了，但完整条件（含敏感值）存服务端，无账号 = 全员可读 |

### 3.2 必备项 vs 加分项（单图查询页，不含看板）

- **必备**（缺一即退回写 SQL）：字段可发现（搜索 + 分组 + 中文别名/注释）· **拖字段即出结果**（无"运行"按钮、无排队）· 筛选/分组是一等公民（时间范围有默认值）· 表格↔图表一键切换 · **每步可回退** · 报错说人话（字段高亮 + 中文提示）· 结果元信息可见（行数/耗时/口径）。
- **加分**：存进图表库 · 导出 · 字段描述 · SQL 兜底通道 · 结果缓存。

> **分界线**：必备 = **第一次查询能成功且敢信**；加分 = **第二次不用从头再来**。

### 3.3 更新版「可用 / 好用」判据

| 判据 | 可用（及格） | 好用（目标） |
|------|-------------|-------------|
| 首图步数 | ≤3 步 | ≤2 步 |
| 首图耗时 | ≤60s | ≤15s（命中缓存） |
| 改筛选 → 新结果 | ≤10s | ≤3s（自动重跑） |
| 首次查询无报错完成率 | ≥70% | ≥90% |
| 分享后对方打开一致率 | ≥90% | ≥99% |
| 从历史找回一次查询 | <60s | <15s（命名 + 筛选 + 收藏） |
| 记录失效后的提示 | 明确文案 + 重建入口 | 保留条件一键重建 |
| 分享内容稳定性 | 不静默漂移 | 分享时可选"锁条件" |

> v1 的「URL <2000 字符」判据**已作废**（链接只带 id）。

## 4. 竞品对照与裁定

### 4.1 一条必须保留的纠偏

火山引擎"智能洞察"实为 **智能数据洞察 DataWind**（VeDI 家族），"智能洞察"是能力标签而非独立产品名。**DataWind 右上角没有"分享/复制链接"按钮**——因为**分享入口就是地址栏**。v1 的竞析只推出"没有按钮"，未推出"地址栏 id 化"链路，导致一度误判；经产品负责人第一手陈述 + 官方文档复核后**已修正**。

### 4.2 与 DataWind 的对齐 / 偏离（官方文档实证）

| 维度 | DataWind 实际做法 | Data Insights 裁定 |
|------|-------------------|-------------|
| queryId 形态 | **8 位纯数字**（示例 `98850742`），自增/雪花 | ❌ **不抄** → **不可猜 UUID v7**（库内存储）+ **21 位 base58 短码**（地址栏） |
| 地址栏形态 | `#/dataQuery?appId=&id=<queryId>&rid=&sid=`，id 在**参数** | ✅ 抄结构 → `/chart-builder?q=<21 位短码>` |
| 地址栏即分享入口 | ✅ | ✅ 抄 |
| 触发方式 | 每次查询**自动**；同一 SQL 执行多次生成**多条**记录（不去重） | ⚠️ 部分抄 → 自动落库 **+ hash 去重** |
| 历史查询 | 可视化查询页「查询历史」图标 | ✅ 抄（R-40） |
| 草稿态 | "临时查询需点保存才入文件夹并重命名" | ✅ 抄（R-41） |
| 清理策略 | 公开文档未说明 | ❌ **不引入后台任务** → 改为软过期 |

### 4.3 业界对照与三条结论

| 产品 | 触发 | key 形态 | 生命周期 / 清理 | 可见性 |
|------|------|----------|-----------------|--------|
| 火山 DataWind | 每次查询自动 | 自增数字 id | 未公开 | 未公开 |
| Superset permalink | 显式复制 | UUID | `key_value.expires_on` + 每日 prune | 无资源权限则看不到 |
| Metabase `/public/question/<uuid>` | 显式创建 | UUID | 可随时停用 | 任何持链者可看 |
| Grafana snapshot | 显式 Publish | 短 key | 强制选 1h/1d/1w/never | 任何持链者 + 组织列表 |
| Kibana permalink | 显式 Share | saved-object id | ILM 默认永久 | 继承认证 |

**结论**：① 业界普遍用**双层**化解自动落库的爆炸（自动只写轻量可 TTL 层，显式才写持久可分享层）；② 清理后旧链**普遍直接失效**（Data Insights 选择**不**照抄，改为直链保活）；③ 无账号体系下"谁能看到"＝**任何持链者**——这正是 id 必须不可猜的原因。

### 4.4 该抄火山的交互（不是它的分享方式）

拖字段入槽位（维度/指标/筛选/TopN/排序/表计算）· 一键 图↔表 切换（含明细表/交叉表）· 顶部 撤销/重做/重置 工具条 · 字段聚合可配（计数/最大/最小/求和/平均/同环比）。

## 5. 核心契约 A：查询记录服务（R-08' / R-30'）

### 5.1 表结构 `bi_query`（本期唯一新增表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `query_id` | UUID **PK** | **不可猜 UUID v7**（明确否掉自增数字方案；时间有序，索引友好）。地址栏不暴露 UUID 本身，见 §5.2 短码契约 |
| `spec_json` | JSONB NOT NULL | 内部含 `v` 版本字段；**应用层 32KB 上限**，超限拒存 |
| `spec_hash` | VARCHAR(64) **UNIQUE** | 内容 hash（规范化 JSON 的 SHA-256）= 去重键 |
| `dataset_id` | INTEGER NOT NULL | |
| `chart_id` | INTEGER NULL | |
| `source_type` | VARCHAR(50) | `build` / `share_url` |
| `row_count` / `duration_ms` | INTEGER | 结果元信息 |
| `ip` | VARCHAR(64) | 留痕字段 |
| `created_at` | TIMESTAMP NOT NULL | 默认 `now()` |
| `last_accessed_at` | TIMESTAMP | 每次读取更新 |
| `hit_count` | INTEGER NOT NULL DEFAULT 0 | 顶点行为事件 |
| **`expires_at`** | TIMESTAMP **NULL** | **NULL = 永久**；创建时写入 `created_at + 90 天`；**打开时不刷新** |
| `owner_id` / `tenant_id` | INTEGER NULL | **为账号体系预留的审计列，本期恒 NULL、不参与任何过滤**；`bi_query` 建表即带，其余四表随 R-22 一并补（Phase C） |

**索引**：`(created_at DESC, query_id)` 复合索引（keyset 分页用）+ `(expires_at)`。
**不加 `status` 字段**、**不写部分索引**（理由见 §5.5）。

### 5.2 id、地址栏与还原

- `?q=<uuid>` = **记录寻址**（唯一定位）。
- `?edit=` / `?datasetId=` 保留为**临时编辑上下文**（不落库）。
- **优先级 `q > edit > datasetId`**；`q` 存在时忽略其余。
- **还原流程**：打开 `?q=` → 记录命中 → 按 `spec_json.v` 复原 → 校验 dataset / 字段有效性 → 失效走可理解降级。

**短码契约（2026-09-19 定稿）**：库内 `query_id` 存 **UUID v7**，地址栏把同一 128 位按 **base58 定长 21 位**编码（字符集 `123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz`，剔除易混的 `0 O I l`）。

| 项 | 取值 | 说明 |
|----|------|------|
| 长度 | **恒 21 位** | 定长便于入口校验与日志对齐；不足左侧补 `1`（`uuid.Nil` = `111111111111111111111`） |
| 码值上限 | `58^21 ≈ 1.076×10^37` | 略小于 `2^128 ≈ 3.40×10^38`，故**不是全值域映射** |
| 覆盖范围 | UUID v7 至时间戳 `8904062744726` ms（约 **2252 年**） | v7 = `timestamp(48) << 80 │ 80 位随机/variant`，21 位足够覆盖；**超出即拒编码，绝不静默截断** |
| 去重稳定性 | 同一 `spec_hash` 恒返回**同一短码**，且不刷新 `created_at` / `expires_at` | 已发出的链接绝不因他人重复提交而改指向或失效（回归哨兵：`impl_test.go` 断言 SET 子句不含 `query_id`） |

> **为何不用 UUID v4**：v4 全 128 位随机，21 位 base58 覆盖不到，会随机拒编码；v7 高位是时间戳，天然落在可编码区间内。
> **为何不追求"可读短 id"**：8 位纯数字可枚举，无鉴权下等于把全库查询历史摊开（见 §8）。

### 5.3 落库触发与去重

**内容 hash 去重 upsert + 异步写入 + 显式动作强制 flush**。

| 策略 | 记录量/天 | 复杂度 | 丢"中间态复用"风险 | 对查询 P95 |
|------|-----------|--------|--------------------|------------|
| ① 每次执行落库 | 2500 | 低 | 无 | **高**（同步 +30~80ms，顶破 1.5s） |
| ② **hash 去重 upsert（选定）** | **1000** | 中 | 无 | 中（重复近零成本） |
| ③ 仅显式动作 | 250 | 低 | **高** | 低 |
| ④ debounce 合并 | 250–500 | 高 | 中 | 低但尾延迟不确定 |

> 假设（**非实测**）：N=50 用户 · 人均建图 5 次/天 · 单次建图 10 次查询 · 唯一配置比 40%。

### 5.4 生命周期：软过期，永不物理删除

- **判定**：`expires_at IS NULL OR expires_at > now()` 即未过期。**单字段判定，不加 `status`**（状态是派生值，重复存储会漂移）。
- **过期后**：从历史列表**默认视图隐藏**；**直链仍可打开、条件 100% 完整还原**；顶部 banner 提示"此查询已过期，条件可能已不适用" + 「另存为新查询」入口。
- `hit_count` / `last_accessed_at` **仍更新**（访问客观发生、零成本）；`expires_at` **不刷新**。
- **配置约束**：`TTL 下限 ≥ 默认视图窗口`（否则默认视图会开始出现过期项，且性能假设失效）。

### 5.5 主理人技术修正（合并前发现的三处）

| # | 问题 | 裁定 |
|---|------|------|
| 🔴 **1** | 数析建议"部分索引 `WHERE status='active'`"加速默认视图。**两处皆不成立**：与"不加 status"冲突；且**即便改用 `expires_at` 也建不出来**——PostgreSQL 部分索引谓词必须 **IMMUTABLE**，而 `now()` 是 **STABLE**，PG 直接拒绝 `functions in index predicate must be marked IMMUTABLE` | **放弃部分索引**，改用普通复合索引 `(created_at DESC, query_id)`，过期判定降为索引扫描**之后的 filter**。keyset 分页带 LIMIT，索引扫描可提前停止，代价可控 |
| 🟡 **2** | 设计矛盾：TTL 默认 90 天 > 默认视图窗口 30 天 → **默认路径上"过滤过期记录"是空操作**（命中零条）。数析基于"需过滤过期"的性能担忧**偏悲观** | 过滤逻辑**仍必须实现**（用户切"全部/更早"或 TTL 调短即命中）；新增配置校验 `TTL 下限 ≥ 视图窗口` |
| 🟢 **3** | 度量口径：路径把 R-44（分页+索引）算进"最短见价值"，但**历史列表不是"分享"的前置** | **拆分两个度量**：分享闭环（不含 R-44）与 历史列表可用 |

### 5.6 落库时序：由「进程内队列」改为同步写（2026-09-19 代码取证修正）

原方案：进程内有界队列（buffered channel）+ goroutine worker 池 + `Flush`。**该队列未落地**，实际实现是**前端在查询成功后同步 `POST /api/queries`**（ChartBuilder 的 `runChartQuery`），后端 handler 直写库、无缓冲层。

改判理由：队列的价值是"把写延迟从用户路径上摘掉"，但本链路的写入本来就发生在**查询结果已经渲染之后**——用户可感知的延迟为零，队列反而白白引入"崩溃丢记录"的窗口（a bounded in-process queue 是易失的，而 HTTP 写不是）。**用同步写同时拿到更简单的实现与更强的持久性保证**：

- 进程崩溃丢记录的风险：**消失**（请求在途即写库；未发请求则前端本就没拿到结果）。
- 显式动作前 `Flush`：**不再需要**（写本身就是同步的）。
- 代价：查询成功后多一次 HTTP 往返（P95 量级 10ms 内），不影响查询本身的 P95 ≤1.5s 目标。

**仍存在的边界**（诚实记录）：① 落库失败只记 `console.error`，不弹错——结果已在屏幕上，少一条分享链接不该把一次成功的查询变成失败弹窗；② 因此**极端情况下可能出现"查询成功但地址栏没有短码"**，用户重新查询即可自愈。

## 6. 核心契约 B：不真删（软删除）

> **产品负责人终局裁决**："都不真删"。范围**已从"仅查询记录"扩展到全部实体**（v3 曾限定为查询记录，后被推翻）。

### 6.1 两条语义不同的"隐藏"，不要混为一谈

| | **实体软删除**（用户主动删） | **记录软过期**（系统 TTL） |
|---|---|---|
| 适用 | `bi_datasource` / `bi_dataset` / `bi_dataset_lineage` / `bi_chart` / `bi_share` | `bi_query` |
| 触发 | 用户显式调用 Delete | 创建时写入 `expires_at` |
| 列表可见性 | **各处均不可见**（含 GetByID → NotFound） | **默认视图隐藏**，切"全部"可见 |
| 直链 / 详情 | **不可访问** | ✅ **仍可访问且条件完整还原** |
| 数据行 | 保留（`deleted_at` 非空） | 保留 |
| 可否恢复 | 数据在库，未来可加回收站（本期不做） | 无需恢复（本就可访问） |

### 6.2 实体软删除契约

1. **字段**：5 张表各加 `deleted_at TIMESTAMP NULL`（NULL = 未删除）。
2. **Delete 语义**：`UPDATE ... SET deleted_at = now() WHERE id = ? AND deleted_at IS NULL`。
3. **级联软删除（必须显式实现）**：改软删后数据库的 `ON DELETE CASCADE` **不再触发**，因此必须在**同一事务**内显式级联，**保持与改造前完全一致的用户可见行为**：
   - 删数据源 → 其数据集 → 其图表 → 其分享
   - 删数据集 → 其图表 → 其分享
   - 删图表 → 其分享
   - **实现要点（易被"顺手优化"改错）**：级联子查询 `SELECT id FROM bi_dataset WHERE datasource_id = ?` **故意不带 `deleted_at IS NULL`**——上一步刚把这些数据集软删了，若加上过滤会查不到，导致图表与分享**级联断链**。
4. **幂等**：重复删除同一条不报错（影响 0 行）。
5. **API 不暴露 `deleted_at`**（`json:"-"`）——前端零改动。
6. **不新建 `name` 唯一约束冲突处理**：`bi_datasource` / `bi_dataset` / `bi_chart` 的 `name` **均无唯一约束**（仅 `bi_share.token` 有 UNIQUE，与删除无关），故软删后重建同名**不会冲突**。
7. **`bi_share.expires_at` 语义不变**——那是**用户显式设定的过期**，仍然生效；与"系统清理导致链接失效"是两回事。
8. **不建回收站 / 恢复接口**（本期只做"不真删"，不做"能找回"的 UI）。

## 7. 前端交互契约

### 7.1 草稿态与另存为（R-41）

| 状态 | 触发 | 行为 |
|------|------|------|
| 新建草稿 | 新查询 | 标「**未保存●**」，不落库 |
| 已落库未改 | 打开旧记录 | 只读引用 |
| 已修改未保存 | 编辑已落库记录 | 标「未保存●」，**不自动覆盖** |
| 更新当前 | 显式更新 | upsert 原 `query_id` |
| 另存为新 | 显式另存 | 生成**新** `query_id`，原记录不变 |

> **禁止默认覆盖**：否则**已分享出去的链接会被静默改写**，是明确的投诉源。

### 7.2 历史查询列表（R-40）

- **可见性**：**默认全员共享**（`owner_id` 无值可填，不参与过滤）。
- **必备**：按数据集 / 时间筛选 · 「复制为新查询」· 「**从我视图中移除**」· 命名 · **默认隐藏过期**。
- **加分**：收藏 · 最近打开。
- **列表项只展示元数据**（数据集名 / 时间 / 行数 / 耗时），**不展示条件值明细**——要看明细须打开记录。
- **分页必须 keyset（游标 / 加载更多）**，禁止深 OFFSET；默认窗口最近 30 天。

### 7.3 「从我视图中移除」（替代"删除"）

- 机制：localStorage 记录 `query_id` 隐藏集合，**仅本机、仅本人可见**，不动服务端、不影响他人。
- 定位：**永久机制**，不是临时妥协——任何记录都可能已被分享，真删会断链。账号体系落地后仍以此为 UX 主路径。
- 已知可接受缺陷：清缓存后标记丢失。
- 未来若遇"彻底抹除"的合规诉求 → 走**脱敏重写**（清空敏感条件值、**保留行与 `query_id`**），**不删行**。

### 7.4 层 A / 层 B 分层

| 层 | 载体 | 特性 | 本期 |
|----|------|------|------|
| **层 A 记录层** | `bi_query` + `?q=<uuid>` | 不可猜 UUID · **无密码** · 软过期但直链保活 | ✅ 做 |
| **层 B 分享层** | `bi_share` + `/share/:token` | 显式受控：bcrypt 密码 + `expires_at` | ✅ 保留 |

**R-43 裁定**：`/share/:token` **新增"由 queryId 生成分享"入口**——把可传播链接收敛到显式动作，对冲"极短链移除心理刹车"的风险。
