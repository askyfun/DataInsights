## 二、能力现状纠偏（本轮仓库实测）

> 本节是对第一轮报告表述的修正。第一轮报告曾把"无计算字段"列为缺口，**该表述不准确**，特此订正。

### 2.1 用户说对的（已实现，勿再列为缺口、勿排期）

| 能力 | 证据链 | 结论 |
|---|---|---|
| **SQL 型数据集**（字段可与物理表不对应） | `bi_dataset` 有 `query_type`（`'table'`/`'sql'`）与 `query_sql`；`service/chart/impl.go:getPlannerSource`/`getPlannerSourceType` 在 `query_type='sql'` 时直接以 `query_sql` 为来源并标 `SourceTypeSQL` | **真接线**，写 SQL 别名即可让字段与库表不一一对应 |
| **虚拟字段（行级列表达式）** | `bi_dataset.columns[].expr` → `executor.go:49 qb.WithColumnMappings(e.dataset.Columns)` → `bun_builder.go:26`（建 `columnMappings[列名]=Expr`）→ `ast.go:122 ApplyColumnMappings` → `GetDimFieldExpr`/`GetMetricFieldExpr`/`GetFilterFieldExpr`/`GetSortFieldExpr` **四处替换** | **真接线**。`amount*0.3`、`[revenue]*0.8` 在维度/指标/筛选/排序里都生效；前端 Dataset 页已有虚拟字段弹窗（name/expr/type/role/comment） |
| 图表内维度组/指标组 | `FieldGroup`/`DimensionGroup`/`MetricGroup` | 已有 |
| 透视表（行列） | 图表类型含透视表 | 已有 |
| 图表级筛选/排序/分页 | 图表级 `filters`/`sort`/`pagination` | 已有 |
| 单图表分享 + 密码 | `bi_share.chart_id` + bcrypt | 已有 |

### 2.2 用户半对的

**"语义层＝我的复合指标"**——只成立**行级**那一半：

| 表达 | DataRay 现状 | 原因 |
|---|---|---|
| `amount * 0.3`（行级复合，再被 `sum()` 包住） | ✅ 可以 | 写进虚拟字段 `expr` 即可 |
| `sum(a) / sum(b)`（比率指标） | ❌ 不行 | 指标结构是 `MetricField{Field, Agg, Alias, Unit, Format}`，**单字段 + 单聚合**，无表达式位 |
| 同环比 / 累计 / 占比 / 聚合间运算 | ❌ 不行 | 同上，且无独立 metric 实体 |

⇒ 你拥有的是 **列级行级表达式**（≈Metabase custom column / Superset calculated column / Looker row-level dimension）；缺的是 **度量级（聚合后）表达式层**（≈Metabase custom summary / Superset virtual metric / Lightdash `type: number`）。**这才是"复合指标"缺失的根因，与权限无关。** 另：无独立 metric 实体 ⇒ 无法"改一处口径全局生效"。

### 2.3 用户不成立的（与优先级无关，需当期处理）

| 缺口 | 证据 | 后果 |
|---|---|---|
| **expr 通路零校验** | `UpdateColumns`（`service/dataset/impl.go:205`）只 `json.Marshal` 入库；`WithColumnMappings` 原样收下 `col.Expr`，**表达式直接拼进 SQL**。对比：表名/字段名走 `datasource.IsValidIdentifier` 白名单、聚合走 `count\|sum\|avg\|min\|max` 白名单 | 可注入子查询等任意 SQL 片段。**安全洞，不是功能债** |
| **虚拟字段无引用校验** | 引用不存在的列只在**查询时**报错 | 用户建完以为成功，直到汇报当天图表空白 |
| **无使用留痕** | `query_logs`/`audit` 不存在 | **不可逆**：查询历史不记即永久丢失，只能从现在开始积累 |

| 能力 | 状态 | 说明 |

### 3.2 自定义表达式能力对照（本轮重点）

| 表达 | Metabase | Superset | Looker | Lightdash | Grafana | **DataRay** |
|---|---|---|---|---|---|---|
| 复合指标 `sum(a)/sum(b)` | ✅ summary/metric 表达式 | ✅ virtual metric | ✅ `type:number` | ✅ `type:number` | ✅ 计算字段 | ⚠️ 仅列级，聚合间运算 ❌ |
| 比率指标 | ✅ 同上 | ✅ 同上 | ✅ 同上 | ✅ 同上 | ✅ | ❌ |
| 同环比 | ✅ `Offset(Sum,-1/-12)` | ⚠️ 需 SQL/Jinja | ✅ `percent_of_previous` / `period_over_period` | ✅ | ⚠️ 靠 join+计算 | ❌ |
| 累计 | ✅ 内置 cumulative | ⚠️ 需 SQL 窗口 | ✅ `running_total` | ✅ | ⚠️ | ❌ |
| 占比 | ❌ 无原生（需 cross join 或 SQL 窗口） | ⚠️ 需 SQL | ✅ `percent_of_total` | ✅ | ✅ 二运算 | ❌ |

关键实现细节：
- **Metabase**：custom expression 三处（custom column / filter / **summary**）；`[Col]` 引用、跨表引用、可引用其他 custom column；编辑器有函数浏览器 + autocomplete + auto-format，**Done 灰化 = 表达式非法**；0.61+ 命名 Metric 可复用、含条件聚合（CountIf/SumIf/DistinctIf）、可引用其他 metric。
- **Superset**：语义层两类——**virtual metric**（允许聚合，如 `SUM(recovered)/SUM(confirmed)`，可 certified）与 virtual calculated column（行级，禁聚合）；Jinja 模板（需 feature flag）。
- **Looker / Lightdash**：用**显式 measure/metric 类型枚举**表达（`type:number` 比率、`percent_of_previous` 同环比、`percent_of_total` 占比、`running_total` 累计）——**这一点值得借鉴：不要做纯自由文本表达式**，否则引擎无法识别语义、UI 无法给提示、无法自动算窗口。

### 3.3 筛选 / 分组交互对照

- **字段级筛选**：Metabase 操作符按类型（number/date/text/category/ID，含 between/relative dates）；Superset 五类控件（filter_select / filter_range / filter_time / filter_time_column / filter_time_grain）。
- **看板级筛选**：Metabase = 控件 → 卡片列映射 + **自动连接含同字段的其它卡片（含跨 tab）** + 默认值；Superset = native filter 的 scope + DataMask + debounce。**竞析建议 DataRay 照 Metabase 模型**（更易实现）。
- **级联/联动**：Metabase Linked filters（父子，**只认表元数据 FK、不认 model 的 join**，custom column/summary 不能做 linked filter）——DataRay 应**放宽为认 dataset 字段**（含虚拟字段），避开这个坑；Superset cross-filter（v5 默认开，需该图有维度）。
- **分组/汇总**：Superset **Pivot Table v2** 有 rows/cols/metrics、series-limit/cell-limit、**rows total/subtotal、columns total/subtotal、transpose、combine metrics**；Metabase pivot 支持交换行列 + subtotal。Top N+"其他"：Metabase row chart 末位"未进前 N"、pie 的 "Minimum slice percentage"。排序会**影响 cumulative/offset 的计算顺序**。

### 3.5 可复用做法建议（竞析）

- **低成本借鉴**：表达式编辑器对标 Metabase（`[字段]` 引用 + 函数浏览器 + autocomplete + **非法时禁用 Done**）；**逐阶段预览**（"expr 零校验"的非权限解药）；时间粒度/分箱改 inline 点选；透视小计照 Superset Pivot v2；TopN+"其他"照 Metabase；看板全局筛选照 Metabase 模型；级联照 Linked filters 但放宽认 dataset 字段。

## 四、权限后置的边界与不可逆项（来自瑞思）

### 4.1 取舍边界表

| 使用场景 | 暂缓权限是否成立 | 一旦越过的失败模式 | 触发越线的信号 |
|---|---|---|---|
| 单人自用 | ✅ 成立 | 无 | — |
| 3–5 人小团队内网（同权、信任、网络隔离） | ⚠️ 有条件成立 | 误改/误删无回溯；离职账号收不回；"谁改的口径"扯皮 | 出现第 2 个敏感度不同的数据集；有人说"这看板只给 X 看" |
| 跨部门 20+ 人 | ❌ 不成立 | 越权可见（薪资/成本/客户 PII 暴露）；口径污染无责；无审计 | 一次跨部门看板铺开；出现"只看本部门数据"需求 |
| 面向外部客户 / 含 PII 与财务 | ❌ 明确不成立 | 合规风险（个保法/等保）；客户 A 看到客户 B | 签约要求数据隔离；BD 说"给客户开个账号" |
| 准备对外售卖 / 集成客户环境 | ❌ 不成立 | 无法交付可信权限承诺；过不了客户安全评审 | 进招投标/安全问卷；要求 SSO、审计日志 |

> **一句话边界：`"电脑在你自己手上"→成立；"账号会交到别人手上"→不成立。`**

### 4.2 可逆性与不可逆项

| 类型 | 内容 |
|---|---|
| **可逆**（补得回来，但成本随数据量增长） | 数据模型加字段 + 迁移（**存量归属需人工回填，越晚越贵**）；31 端点接线（机械改造，路径清晰）；前端逐页权限态 |
| **不可逆 / 代价极高** | ①**无使用留痕**——查询历史一旦没记就永久丢失，事后无法重建"当时谁看了什么"，只能从现在开始积累；②**口径污染历史**——被错误表达式改过的图表历史数值无法恢复真值；③**外部承诺**——对客户/合规方说过"我们有权限控制"，再补就是打脸成本 |

**把不可逆项转成可逆项的最小动作（瑞思）**：**`owner_id`/`tenant_id` 从第一天写进表结构（只加字段、不做鉴权）+ 使用留痕从第一天开始记。**
**体验代价**：后补权限 = 一次"功能冻结期"，所有端点要回归、期间新增功能停摆。

### 4.3 用户视角 Top 5（体验优先框架下）

1. **图表拖拉拽构建**（服务分析师，兼顾业务）——当前卡点：改一维要重进弹窗；改完业务能自己拖出临时分析图，不等分析师排期
2. **全局筛选/联动**（业务、管理者）——当前断点：看"本月华东"要逐图各改一遍；改完一屏切地区/时间，全板联动
3. **看板 + 看板分享**（管理者、外部接收者）——当前断点：汇报要逐图截屏；改完发一个链接即见完整看板
4. **可视化指标层/口径复用**（业务、数据管理员）——当前卡点：指标=单字段+单聚合，做不出比率/同环比；改完业务方直接调"转化率"，全公司口径统一
5. **搜索/收藏 + 导出**（全部）——当前断点：看数要"找得到、带得走"；改完报表可下载进周会材料

### 4.4 不可后置的底线项（与优先级无关）

1. **表达式通路零校验**——安全洞，不是功能债：任何能编辑数据集的人（改天即任意使用者）可注入子查询把整库拖走。
2. **虚拟字段无引用校验**——用户建完以为成功，直到汇报当天图表空白，排查成本全压使用者。
3. **无任何使用留痕**——一旦泄露，连"泄露了什么、范围多大"都说不清，无法止损定责；**且事后补不回来**。
4. **无导出**——当前无导出反而是"无权限下的安全缓冲"；若先加导出再补权限，等于给越权数据开外带通道 ⇒ **导出必须与留痕（及权限）同批上线**。

### 6.3 阶段详解（要点）

- **P0 地基**：目标＝堵合规与不可逆漏洞。交付 T-07 校验器（白名单 + `internal/expr/validate.go`）、T-08 `query.Guard`（仅单条 SELECT + 只读账号）、T-09 口令加密 + 响应脱敏、虚拟字段引用校验（保存即报错）、filter-state、错误契约（错误码 + 修复建议）、`bi_query_log`、owner/tenant（nullable + 迁移 + 默认回填当前唯一账号）。验证：G1/G2/G3 用例全过 + 留痕写入断言 + 单测全绿。退路：窗口函数方言未确认**只影响 R-06**，不影响本阶段。
- **P1 体验核心**：目标＝从"能用"到"愿天天用"。验证：SC-1/1B/2/3A–3D、MC-3 + 埋点 + 错误可诊断 ≥80% + 建图 ≤5 步。可延后：R-21 下钻（先上多维度分组 + 小计）。退路：**R-06 窗口函数不可用 → 拆期**（先 `simple`+`ratio`，同环比/累计/占比后置）。
- **P2 体验补全**：交付 R-16 受控导出（限行 + 限字段 + 强制留痕，依赖 R-08）、R-09 缓存加速、R-15 搜索收藏、筛选操作符、推荐简版、看板分享。退路：R-09 未达 800ms → 降级为抽样 + 异步加载并公布护栏。

### 6.7 利益相关者沟通要点（三版）

**高管版**
1. 本轮不投权限，把钱花在"用户愿意天天用"的差异点上——**复合指标 + 看板**。
2. 目标：建图 **≤5 步、P50 ≤3min**，让分析师自己出数，不等排期。
3. **见价值约 36–49 人日（估算）**；3 人并行到体验核心收口约 **5–7 周**。
4. 权限是"**触发器**"而非阶段：哨兵 = 第 2 个敏感度数据集，命中即立项。
5. **不可逆埋点（owner/tenant + 留痕）当期即做，成本 ≈5–7 人日，逾期不可回填**。

**工程版**
1. **便宜活（后端已就绪、只差接线）**：时间粒度 inline、TopN+"其他"（现为死链）、透视小计照 Superset Pivot v2——**半天级接线**。
2. 关键路径：`T-07 → 错误契约/filter-state → R-06 → R-04 → R-05`；**勿让 R-06 被窗口函数阻塞**（先 `simple`+`ratio`）。
3. R-19 / R-20 / R-21 可与 R-06 并行；R-05 与 R-04 可部分并行。
4. **待确认项需先做探针**：DB 方言窗口函数支持、统一错误码。
5. **G1/G2 是 Release Blocker**，禁止黑名单式校验。

**设计版**
1. 看板画布需支持"全局筛选控件 → 卡片列映射 + 自动连接同字段卡片 + 默认值"（对标 Metabase）。
2. 表达式编辑器对标 Metabase：`[字段]` + 函数浏览器 + autocomplete + **非法时禁用 Done** + 逐阶段预览。
3. 分组交互需暴露 **breakout 槽 / 小计开关 / TopN 控件**；"撤销"先做 Reset（满足 80%）。
4. 字段列表（80+ 列）需分区 + 类型图标 + **搜索** + 折叠，滚动 ≤2 屏。
5. 移动端本轮**仅断点自适应**，原生 App 为 Non-goal。
