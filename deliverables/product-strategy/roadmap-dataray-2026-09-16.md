## 3. 关键路径与并行机会

```
G1 expr 校验器
   └─→ R-08' 落库内核 ──→ R-30' 寻址还原 ──→ R-31' 复制地址栏 ──→ 【M2 分享闭环】
                               │
                               ├─→ R-34 出口 Guard
                               └─→ { R-40 历史列表 ‖ R-41 草稿态 } ──→ 【M3】
                                        └─ R-44 并入 R-40 门槛
   R-42 软过期（建表后即并行，尾随）
   R-33 查询期校验（全程并行，不阻塞关键路径）
   R-06 / R-19 / R-20 / 拖拽增强（管数据正确性，与状态层无强依赖，可并行）

──【图型扩展轨（本轮新增·独立并行·不入上方关键路径）】──
   R-21 多维度分组引擎【Batch 0 前置】──→ Batch1 P0（R-48 · R-50 · R-51 · R-53）
        └─（堆叠/百分比堆叠/双轴＝R-21 验收子项）
                                             └─→ Batch2 P1（R-54…R-60，R-58 依赖 R-21）──→ Batch3 P2
```

**瓶颈分析**：v1 的"URL 客户端编码"本可**独立先行**（纯前端），换成服务端落库后，**落库内核成为分享的前置依赖**——这是"最短见价值"从 15–24 拉长到 17–28 的根因。

**图型扩展轨与关键路径的关系**：图型扩展（R-21 + R-48~R-68）落在前端 `ChartBuilder` 与后端聚合白名单，**与分享链路的落库内核 / URL 寻址无依赖**，因此**不增加关键路径长度**；它只与「拖拽建图增强」争用同一前端文件，**轨内串行即可**。→ 结论：**可与主线并行推进，不必排在其后**（但 Batch 2/3 建议让位于主线 M1）。

### 5.1 R-04 看板 / R-05 跨图联动 — 延后出当期

### 5.2 R-21 钻取与相位变动

- **钻取移出**（保留多维度分组）：依赖下钻语义重写 + URL 状态叠加栈，仍延后。
- **相位变动（本轮·唯一）**：「多维度分组」由 **Phase 1 普通 P0 条目 → 图型扩展轨 P0 前置（Batch 0）**。实测依据：`chartDefinitions.ts` 中 `bar` **仅 `x_axis`(dimension) + `values`(metric) 两槽位，无任何 series/分组槽位**，全库 grep `stack|orient|horizontal|inverse` **零命中** → **单系列柱状图上堆叠无意义**。故「堆叠 / 百分比堆叠 / 双轴」**不是独立项，是 R-21 的验收子项**（独立增量仅 option 拼装 ≈0.5–1 人日，**不可脱离 R-21**），R-21 因此成为其**强制前置**。**人日保持 6–8 不变，仅相位与归属变**。详见 §2.4。

## 6. 风险栏

| 风险 | 状态 | 说明 / 阈值 |

| **异步落库在进程崩溃时丢记录** | 🔴 未消除 | 进程内队列 → SIGKILL 时未落盘记录丢失。缓解：显式动作前 `Flush`、队列满同步兜底。**根治需 WAL / 本地持久队列，超出本期范围** |
| **无鉴权 + 全员共享 → 全库查询条件可被任意浏览** | 🟡 **已接受** | 产品负责人明确接受。**打破条件**：① 出现账号 / 多租户体系 ② 网络越出内网 ③ 接入跨团队或外部用户——任一成立即失效，须补 owner 过滤 + 可见性控制 + 鉴权 |
| **`owner_id` 有字段无值** | 🟡 半消解 | 全员共享后 `owner_id` 退为审计字段；"个人删除"改本地隐藏。既有 4 表的 owner 埋点**仍欠账**（不可逆） |
